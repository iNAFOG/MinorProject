# Repository audit — 22 November 2026

The audit covered every source file, test, configuration, benchmark, script and Markdown document. Each suspected defect was first reproduced with a probe, then fixed, then covered by a regression test in `tests/test_audit_fixes.py`. Afterwards every offline experiment was re-run and compared with the saved artifacts. No Gemini or other paid requests were made.

**Test suite:** 84 passing before the audit; **101 passing** after it (17 new regression tests).

## Defects fixed

| # | Defect | How it was shown | Fix |
|---|---|---|---|
| 1 | **Correct code failed verification.** The AST interpreter's 10,000-step budget was shared by every case in a check. | A correct summing loop with 12 cases over 200 values failed with `interpreter step limit`. | `SafePython.invoke()` gives each top-level case a fresh budget. A runaway case is still stopped. |
| 2 | **Verification read truncated files.** Checks used the agent-facing `read`, which stops at `max_output_chars` (12,000). | A correct 27,122-character `solution.py` failed with `SyntaxError`. | Checks read the whole file. Agent reads stay bounded. |
| 3 | **A repeated `run` was credited with an earlier run's output.** Workspace folders were named `task-0000` in every new process and reused. | First run wrote `solution.py`. A second run whose model wrote nothing was reported `verified=True`. | Each task run gets a new workspace folder. Nothing is deleted. |
| 4 | **Sandbox memory hole: bytes repetition.** The allocation check covered `str/list/tuple` but not `bytes`. | `b'ab' * 200000000` returned a 400 MB value with no limit hit. | `bytes` is included in both the pre-allocation check and the size bound. |
| 5 | **Sandbox memory hole: `%` formatting.** A format width allocates before any size check. | `'%0300000000d' % 1` built a 300 MB string before being rejected. | String/bytes `%` formatting is rejected. Numeric modulo still works. |
| 6 | **Adapter crashed on common server responses.** `tool_calls: null`, `usage: null`, `prompt_tokens: null` and empty `arguments` raised `TypeError` or `JSONDecodeError`. | Loopback server reproduction. | Null fields are treated as absent. Empty arguments become `{}`. Malformed or non-object JSON becomes a failed action the model can see. In games it wastes the move, as the rules state. |
| 7 | **One hallucinated tool name ended the episode.** `Runtime.call` raised before its error handling. | A model that called `read_file` once could not recover. | Unknown or disabled tools are never executed. They use one tool call and return an error observation. |

Smaller corrections:

- The Git commit in experiment metadata was read from whatever directory the command ran in. It now comes from the project's own directory.
- Multi-condition `benchmark` ignored the configured `epsilon`. It now passes it through.
- The top-level multi-condition `comparison.csv` printed `verified_completion_rate` pooled over adaptation and evaluation episodes, which looks like a held-out rate but isn't one. Explicit `held_out_*` columns were added, and the console summary now prints them.
- Documentation:
  - 39 Markdown links pointed to `/C:/Users/Acer/Desktop/minor/…` on a previous machine. They are now repository-relative, and every link in `README.md` and `docs/` resolves.
  - The professor guide (12 October) said no real LLM had been run, and cited 37 tests and the old project path. It now carries a dated update.
  - The README, `architecture.md` and `experiments.md` describe the corrected behavior.

Checked and found correct: all nine `configs/e*.yaml` files match the code's E0–E8 condition table. The numbers quoted in the Gemini Battleship, Battleship pilot, tic-tac-toe pilot, controls and smoke-run documents all reconcile with their saved `game_summary.json`, `episodes.jsonl` and `changes.jsonl`, including request accounting (49 + 62 = 111 of 120).

Not changed: `reports/presentation-build/*.mjs` hard-code tool paths on the previous machine (`C:/Users/Acer/.codex/...`). Those generated the existing slides and cannot run here without that toolchain. Saved run artifacts under `runs/` were left untouched.

## What the results mean

The fixes change correctness at the edges: long files, many test cases, sloppy server responses, hallucinated tools and repeated runs. They do not change any headline result, because the saved fixtures never hit those cases. The research conclusions in the existing documents still stand:

- The offline coding results demonstrate the mechanisms only.
- The Gemini Battleship pilot accepted a note that did not transfer: held-out coverage fell from 73.3% to 60%.
- The tic-tac-toe pilot accepted nothing.
